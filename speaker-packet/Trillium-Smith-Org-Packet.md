## 3. Ways to host Trillium

Pick one — or combine. All formats include live hands-free coding unless you request slides-only.

### A. Live demo talk (30–45 min + Q&A)
**"I Code With My Voice — Here's How"**

Trillium codes live, hands-free, and narrates what he's doing: dictation, navigation by voice, structural editing with Cursorless, and how AI agents fit in. Best "wow + aha" for general audiences.

Takeaways:

- What hands-free coding actually looks like day-to-day
- Talon Voice + Cursorless in plain language
- Alternative ways of interacting with computers anyone can borrow (voice, dictation, automation)

Good for: meetups, conferences, school assemblies, accessibility awareness events.

### B. Interactive workshop (60–90 min)
**"Try Voice Control Yourself"**

Attendees try dictation, basic voice navigation, and Cursorless-style structural thinking (no setup required to follow along; volunteers can try live with guidance). Ends with an accessibility brainstorm: "what would you automate if you couldn't use a keyboard?"

Takeaways:

- First-hand feel for voice-driven workflows
- Practical accessibility mindset for designers/devs
- Resources to keep exploring (Talonhub, Cursorless, awesome-talon)

Good for: dev teams, bootcamps, university classes, accessibility ERGs.

### C. Fireside / Q&A / Panel (30–60 min)
**Career change, accessibility, AI tooling**

Conversation about massage → code, building in public, open source, disability/accessibility, and where AI + voice fit in the future of programming. No live coding required, but Trillium can demo a 5-minute bite if you want it.

Good for: panels, podcasts, lunch-and-learns, community groups.

## 5. Tech & room checklist

Kept simple on purpose. Trillium brings his own mic + machine.

**Please provide:**

- [ ] Large screen / projector + HDMI (code must be readable from the back row — min 24pt font assumed)
- [ ] Wi-Fi access + power outlet
- [ ] 1 chair + small table (standing optional)
- [ ] Quiet-ish room — voice recognition works best with low background noise
- [ ] For virtual: screen-share + computer audio permission, captions on if available

**Trillium brings:** laptop, wireless mic, Talon + Cursorless setup, demo project.

**Timing note:** voice coding is vocally demanding — for sessions over 60 minutes, a 5-minute voice break in the middle is appreciated.

## 6. Accessibility

This talk is about accessibility, so we try to model it:

- Live captions strongly preferred (in-person CART or virtual auto-captions)
- Please mic audience questions (in-person) or have them typed (virtual)
- Slides/code: high contrast, large font, dark or light OK
- Let us know about interpretation, wheelchair access details, or sensory needs and we'll adapt

If your org has an accessibility checklist, send it — we'll follow it.
